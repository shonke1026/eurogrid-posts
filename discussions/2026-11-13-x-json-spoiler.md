# Xのネタバレ配慮3本形式とx.jsonの形

状態： Claude回答済み

## 素材

- 11/12 の決定で、X の案は posts/<フォルダ>/x.json に置き、中身は text（本文）と reply（出典の返信、媒体名だけ）の2つだけにした。出したあと status_ids と posted_at を足す（platforms/x.md の「x.json」）
- 一方、platforms/x.md の「形」では、レースから24時間以内に結果にふれる投稿は「本文（結果なし）→ 返信1（中身。⚠️ネタバレ：で始める）→ 返信2（出典）」の3本になる。この3本は今の x.json に入らない
- scripts/check_post.py は今、x.json の text・reply 以外の項目を NG にし、reply を出典の返信として検査する（URL・@・ドメインに見える名前で NG）
- ポルトガルGP（11/20〜22）で、この形の投稿が出る見込み

## 質問票（ユーロ）

- Q1. 24時間以内の結果の投稿だけ、x.json に replies（[返信1の中身, 返信2の出典]）を置けるようにするか。ほかの案（返信1は x.json の外に置く、など）がよいか
- Q2. Q1 で replies を認める場合、機械チェックは「返信1は長さとAmazonだけ、最後の返信だけ媒体名だけ」でよいか
- Q3. 決めたい期限は 11/18 でよいか（ポルトガルGPの準備 11/19 の前）

## Claude回答

### 2026-11-13 17:54（即時の受け口）

- Q1. replies を認めるのがいい。ただし名前と形は Threads の post.json に合わせる。
  - 形：`text` ＋ `replies`（[返信1の中身, 返信2の出典]）。`reply` と `replies` はどちらか片方だけ（両方あったら NG）。24時間以内の結果の投稿以外は、今までどおり `text` ＋ `reply`
  - 理由：Threads の post.json はもう `replies` のリストを使っている（posts/2026-11-12-th-martin など）。check_post.py の `_replies()` も `replies` を読めるので、変えるのは X_JSON_KEYS と出典の検査の当て先くらいで済む
  - 返信1を x.json の外に置く案はおすすめしない。platforms/x.md の「投稿の画面には x.json の text と reply をそのまま使う（その場で書き直さない）」が崩れて、出す前の正本が2か所になる。いちばんネタバレに気をつける中身が、機械チェックの外に出るのも逆
  - 出したあとの `status_ids` は、本文・返信1・返信2の順に3つ。数は「1＋replies の数」とそろうので、ここも機械で見られる
- Q2. 基本はそれでいい。足したいのは次の3つ。
  - 返信1が「⚠️ネタバレ：」で始まっているか（platforms/x.md の決まりで、機械で確実に見られる）
  - replies はちょうど2つ（3本形式の形を固定する。1つや3つは NG）
  - 返信1の長さは x の数え方で 280 以内（いまの check("x") と同じ）。出典の返信は今の x-source の検査（URL・@・ドメイン）をそのまま
  - 本文が結果をにおわせていないかは機械では見られない。そこは今までどおり auditor の目で見る。check_post.py が通っても「ネタバレ配慮OK」とは言えない、と auditor.md か x.md に1行あると安心
- Q3. 11/18 でいい。check_post.py の変更とテストの追加は小さいので、決まれば当日中に入れられると思う（未確認。作業量は見積もりだけ）。11/19 の準備の前に、過去の投稿で x.json を1つ作って check を通す試しを1回やっておくと、本番で詰まらない
