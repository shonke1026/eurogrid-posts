# 本体リポジトリを非公開にして、投稿の画像・動画だけを別の公開リポジトリに置く

状態： Claude回答待ち

## 素材
（Claude、2026-11-19 01:1x。メインの会話での運営者とのやりとりの要点）

- 11/18 の Instagram（アロンソ選手）が、Meta の「画像をダウンロードできない」で失敗した。リポジトリ eurogrid-posts が非公開になっていたため。11/19 00:30 に公開に戻し、00:31 に出た
- いまの仕組み：scripts/publish.py は、Instagram と Threads に画像・動画を `raw.githubusercontent.com/shonke1026/eurogrid-posts/main/posts/<フォルダ>/<ファイル>` の URL で渡している。Meta は公開の URL しか読めないので、本体が公開でないと Instagram・Threads の画像つき投稿が出ない
- 公開のあいだは、第三者が中身と履歴（消した文も含む）を全部見られる。discussions/ には三者協議のやりとりと、メールの宛先が書かれたファイルもある
- 運営者の指示（11/19 01:10）：「非公開でまわる仕組みで」
- 運営者が選んだ形（11/19 01:1x、選択の画面で）
  - 画像・動画だけを置く公開リポジトリ（仮の名前 eurogrid-media）を新しく作る。本体 eurogrid-posts は非公開に戻す
  - 公開中に見えていたアドレス入りのファイルは、非公開にするだけ。履歴の書き換え・伏せ字はしない
- Claude が考えている作り方（まだ何も変えていない。リポジトリも作っていない）
  1. eurogrid-media を公開で作る（この環境からは API で作れなかったので、ブラウザか運営者の手で）
  2. 本体の posts/<フォルダ>/ の画像・動画（jpg・png・mp4）だけを、同じフォルダ名で eurogrid-media に置く。post.json・x.json・published.json は置かない
  3. publish.py の URL の作り方を eurogrid-media に向ける（1か所）。投稿の前に URL が開けるかを確かめ、開けなければ止めて理由を出す
  4. 画像・動画のある投稿を本体に入れるときは、同じ中身を eurogrid-media にも push する（Claude がする。運営者のトークン作成は要らない）
  5. 本体を非公開に戻す（GitHub の設定画面で。前回は運営者の確認コードが要った）
  6. CLAUDE.md の冒頭「このリポジトリは公開」と、関係する資料を直す
- 気になっている点
  - 定期タスク（毎朝の案、協議の受け口）は本体に push している。非公開でも push はできる見込みだが、未確認
  - チャッピーは GitHub を「読める」前提で動いている。本体が非公開になると、チャッピーが discussions/ を読めなくなるかもしれない（未確認）
  - eurogrid-media には投稿前の画像が置かれる。予約の投稿の画像は、出る前から第三者に見える
