### 2026-11-20（毎朝の定期タスクから）
質問票が「Q1.」だけで空だったので、素材の叩き台ぜんたいへの意見として答える。番号は叩き台の項目の順。

1. 役目の切り分け：賛成。監査（出す前）・網羅性（拾い漏れ）とは別の、3つ目の役目「出たものが出したかったとおりか」でいい。結果もほかの2つに混ぜない（CLAUDE.md の11と同じ考え方）。
2. 起点：予約の時刻ではなく、まず「予約の時刻（手で出すものは OK の時刻）＋15分」で見る。その時点で published.json や x.json に記録が無ければ、それ自体を「出ていない」とする。11/18 の X が半日止まった件は、実際に出た時刻を起点にすると捕まらないため。
3. 15分後に見るもの：叩き台の6つで足りる。優先は ①出ているか ②出典の返信が付いているか（ネタバレ配慮の回は返信の1行目が「⚠️ネタバレ：」か）③X の返信にカードが無いか ④Instagram なら Facebook にも出ているか ⑤本文が一字一句同じか ⑥画像の枚数と順番。⑤は目で読まず、公開ページの本文を取って post.json・x.json と機械で突き合わせるほうが確実。
4. 60分後：「まだあるか」は賛成。急ぎのコメントはコメント確認の定期タスク（12:27・18:27・22:27）と重なるので、ここではその投稿への返信だけを見る。表示の数は毎朝の 1b で取っているので、60分の数は外してよい（省けるなら手間が減る）。
5. 見る人：別のエージェントで賛成。渡すのは点検の手順・post.json・x.json・時刻だけ。ただし X と Facebook は L5320-note の Chrome が要るので、PC が動いていないと見られない。そのときは「見られなかった」と書いて終える。
6. 動かし方：おすすめは「1回の配信のまとまりごとに、最後の1本の15分後と60分後に一度きりの合図を2つ」。1本ごとに2つだと1日10本で20個になり、合図の管理がミスのもとになる。毎朝の定期タスクの 1b（前日の数字を見る手順）に「前日の投稿が全部出ているか」の照合を足すのは、漏れを拾う予備として安い。どちらも指示文の変更なので、運営者の OK のあと。
7. 結果の置き場所：daily に1行ずつ、だめなときだけメール、で賛成。件名は「【Eurogrid】事後点検：〜」で、本文の最初に「何が・どの投稿で」を1行。
8. 読むだけ：賛成。消す・出し直すは運営者の OK のあと（14_mistakes.md の 11/14 の件と同じく、消すほうが乱れることもある）。
9. 間隔のミスの基準値：14_mistakes.md の基準値の欄に「11/10 の Threads、論調比較 10:07 と小椋藍選手 10:16」と書いてあり、「2026-11-19 運営者が確認」とある。候補のとおりで合っている。
10. ユーロ・チャッピーの記録：Claude 側からは見られないので、わからない。残っていれば、そちらを正にするのに賛成。
